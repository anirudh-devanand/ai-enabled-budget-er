# ADR 0004: MFA - TOTP first, passkeys next

Status: accepted

## Context

A finance app needs a second factor. Options: TOTP (authenticator apps), SMS, platform passkeys.

## Decision

Ship TOTP now; add passkeys (WebAuthn) in the hardening slice; never SMS (SIM-swap risk).

Flow: users enroll by scanning an otpauth QR provisioning URI and confirming one code. Once
enabled, password login returns a short-lived (5 min) challenge token instead of a session; the
client exchanges challenge token + TOTP code for the access/refresh pair. TOTP secrets are stored
encrypted with the application data-key (see future KMS ADR; local dev uses a settings-provided
key).

## Consequences

- Works offline, no carrier dependency, standard authenticator apps.
- Recovery codes are not in slice 1; they must land with the hardening slice before any real
  user data is connected.
